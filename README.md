# Generated Feral Lanterns

A focused **NeoForge 1.21.1** compatibility mod for **Torchmaster**.

Its normal rule is strict:

> **World-generated lanterns are converted. Normal player-placed lanterns are not.**

The default replacement set contains both `minecraft:lantern` and `minecraft:soul_lantern`. Matching lanterns generated by vanilla or by structure/world-generation mods are replaced with `torchmaster:feral_flare_lantern` when a newly generated chunk first enters the server.

## Requirements

- Minecraft **1.21.1**
- NeoForge **21.1.41+**
- Torchmaster **21.1.x**
- Java **21**

This project targets NeoForge `21.1.251` for development.

## Normal new-chunk behavior

NeoForge exposes `ChunkEvent.Load#isNewChunk()`, which identifies a chunk that has just been generated and is being loaded for the first time on the logical server.

For a new chunk, this mod:

1. Captures a read-only snapshot of matching generated lantern positions and exact block states.
2. Defers all world mutation until the normal server tick. NeoForge warns that interacting with the level directly during `ChunkEvent.Load` can deadlock because the chunk may not yet have reached `FULL` status.
3. Re-checks each candidate before replacement. A candidate is changed only if the same block state is still there and the position has not been recorded as a normal runtime placement.
4. Replaces it with `torchmaster:feral_flare_lantern`.
5. Marks the chunk as processed with persistent NeoForge chunk data so that it is never later treated as a migration candidate.

If a newly generated chunk unloads before its deferred conversion runs, a persistent retry marker causes conversion to resume safely the next time that chunk loads.

## Player-placement protection

Normal runtime block placement is **not** a conversion trigger.

In addition, while a chunk is still eligible for the optional old-world migration, placements reported through NeoForge's normal `BlockEvent.EntityPlaceEvent` are stored as protected positions. The conversion step checks that protection again immediately before writing.

This covers the important race case where a player removes an old/generated lantern and places an identical vanilla lantern at the same position after the chunk was snapshotted but before migration executes.

Once a chunk is marked processed, it is never rescanned, so later player placement in that chunk cannot be converted by this mod.

### Provenance boundary

The protection above applies to normal placements that occur **after this mod is installed** and can therefore be observed.

Minecraft does not store historical per-block provenance. A lantern that already existed in an old chunk before this mod was installed carries no reliable record saying whether it came from structure generation or a player. No mod can reconstruct that distinction perfectly from the block alone.

Commands such as `/setblock`, external world editors, or other mods that directly mutate block states may also bypass NeoForge's normal entity-placement event and therefore do not provide reliable player-placement evidence.

## One-time existing-world prompt

The first authorized player to enter a world while no migration choice has been recorded receives a one-time screen with two choices:

### Convert Existing Lanterns

Pre-existing chunks become eligible for a one-time migration. Matching lanterns are snapshotted and converted incrementally as old chunks load. Old chunks already loaded while the decision was pending are queued when the choice is accepted.

Normal post-install placements that the mod observed are excluded.

**Important:** pre-install lanterns have no historical provenance. This option can therefore convert player-built lanterns that already existed before the mod was installed. The screen explicitly warns about this and recommends backing up the world first.

### New Chunks Only

All pre-existing chunks are left unchanged. Only chunks newly generated after installation are converted.

The choice is stored in world `SavedData` and cannot be repeatedly prompted or silently changed later.

In singleplayer, the world owner can choose. On a dedicated server, an operator with permission level 2 or higher can choose.

## Default source block tag

The mod uses:

`generatedferallanterns:source_lanterns`

Defined at:

`src/main/resources/data/generatedferallanterns/tags/block/source_lanterns.json`

Defaults:

- `minecraft:lantern`
- `minecraft:soul_lantern`

A modpack datapack can extend the tag with additional lantern block IDs without changing Java code.

## Orientation handling

Vanilla lanterns use the `HANGING` property. Torchmaster's Feral Flare Lantern uses a six-way `FACING` property.

- floor lantern -> Feral Flare `FACING=DOWN`
- hanging lantern -> Feral Flare `FACING=UP`

That mapping matches Torchmaster's own placement logic, where the Feral Flare Lantern faces opposite the clicked surface.

Tagged third-party lanterns that do not expose vanilla's `HANGING` property use the target block's floor-facing orientation.

## Performance behavior

The scanner first checks each chunk section's palette with `LevelChunkSection#maybeHas`. Sections that cannot contain a tagged source lantern are skipped instead of brute-force checking every block in the chunk.

Conversion work is deferred and rate-limited to **16 chunk plans per server tick**. The queue never force-loads chunks solely to convert them.

The larger performance consideration is intentional gameplay behavior: every converted lantern becomes a Torchmaster Feral Flare Lantern block entity capable of spreading invisible light. In structure-heavy worlds, replacing every generated lantern can create many Feral Flare Lanterns, so Torchmaster's own block-entity/light-spreading cost may become significant even though this mod's scanner is bounded.

## Known edge cases

- **Pre-install player lanterns in old chunks:** impossible to distinguish reliably from pre-install generated lanterns. Only the optional migration can touch them; choosing **New Chunks Only** avoids the issue entirely.
- **Direct block mutation:** commands, editors, or mods that bypass `EntityPlaceEvent` cannot be identified as normal player placements by this provenance system.
- **Waterlogged vanilla lanterns:** Torchmaster's Feral Flare Lantern does not expose vanilla lantern waterlogging state, so that property cannot be preserved during replacement.
- **Third-party lantern orientation:** blocks added to the source tag that do not use vanilla `HANGING` semantics fall back to the Feral Flare floor orientation.
- **Large numbers of Feral Flare Lanterns:** Torchmaster behavior, not the conversion scan itself, may be the dominant runtime cost in highly structure-dense worlds.

## Building

This is a NeoForge ModDevGradle project and intentionally does **not** compile against Torchmaster Java classes. The integration resolves the target block through Minecraft's registry by the verified ID `torchmaster:feral_flare_lantern`, reducing binary API coupling.

The repository includes the standard Gradle wrapper from the NeoForge MDK and targets Gradle 9.2.1.

Build on Linux/macOS:

```bash
bash ./gradlew build
```

Build on Windows:

```powershell
.\gradlew.bat build
```

The output JAR will be under `build/libs/`. GitHub Actions also runs the Gradle build on pushes and pull requests.

## Implementation map

- `GeneratedFeralLanterns.java` — registrations and event wiring
- `LanternChunkEvents.java` — new-chunk / old-chunk classification
- `LanternReplacer.java` — palette-aware snapshot and safe replacement
- `ConversionWorkQueue.java` — deferred, rate-limited server-tick conversion
- `RuntimePlacementProtection.java` — post-install normal-placement provenance protection
- `MigrationSavedData.java` — one-time world decision
- `PendingMigrationChunks.java` — already-loaded old chunks awaiting the prompt decision
- `MigrationEvents.java` — opens the one-time choice UI
- `MigrationMenu.java` / `MigrationPromptScreen.java` — menu and client screen
- `MigrationChoicePayload.java` / `ModNetworking.java` — authenticated client-to-server choice
